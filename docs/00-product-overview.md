## 1. โจทย์

สร้าง **แพลตฟอร์มรับงาน commission** สำหรับครีเอเตอร์สายภาพ/วิดีโอ/adopt
โดยแพลตฟอร์มทำหน้าที่เป็น "หน้าร้าน + ระบบหลังบ้าน" ให้ครีเอเตอร์ ไม่ใช่แค่ฟอร์ม Google Form + DM

**ข้อกำหนดจากผู้ใช้งาน (ที่ต้องรักษาไว้):**

| ข้อกำหนด | รับมาแล้วในแผนนี้ |
|---|---|
| Login ด้วย Google | Better Auth + Google OAuth (ดู `01-architecture`) |
| Free tier ครอบคลุมการใช้งานทั่วไป | ทำงานครบ loop รับงาน–ส่งงานได้ฟรี (ดู `03-plans`) |
| Paid tier ปลดล็อกเพิ่ม (แจ้งเตือน ฯลฯ) | Pro/Studio + entitlement layer |
| ใช้งานง่าย modern | Design system + IA ใน `04-ux-and-ia` |
| ประหยัดทรัพยากร | Cost strategy เป็นหัวข้อหลักใน `01-architecture` |
| Deploy บน Vercel + Neon + Vercel Blob | ทั้งหมดอยู่บน 3 ตัวนี้ ไม่เพิ่ม vendor โดยไม่จำเป็น |
| มีหน้าบ้าน + backoffice | `(public)` route group และ `(app)` route group |
| Next.js | Next.js 16.2 App Router |

## 2. ชื่อโปรเจกต์ (ยังไม่ล็อก)

ในเอกสารจะเรียกว่า **the platform**. ตัวเลือกชื่อที่แนะนำ (สั้น, พิมพ์ง่าย, .com/.art ยังพอหาได้):

- **Commi** / **Commish** — ตรงตัว จำง่าย สายอาร์ตสากลเข้าใจทันที
- **Slotly** — เล่นกับคำว่า "slot" ที่ชุมชนอาร์ตใช้กันอยู่แล้ว ("slots open!")
- **Queuely** / **Kyu** — เน้นจุดขายเรื่องคิวงาน
- **Rabbi.art**, **Palet**, **Inkq** — สายชื่อแบรนด์

> เลือกก่อนเริ่ม Phase 0 เพราะมีผลกับ package name, domain, OAuth consent screen

## 3. ตลาดและคู่แข่ง (สรุปจาก research)

| แพลตฟอร์ม | โมเดล | จุดแข็ง | ช่องว่างที่เราแทรกได้ |
|---|---|---|---|
| [VGen](https://vgen.co/) | หัก % + escrow | Custom Proposal / Instant Order, Work Queue board ที่ sync ขึ้นหน้า public queue อัตโนมัติโดยไม่เปิดเผยตัวตนลูกค้า | ผูกกับ VTuber/streamer niche, ไม่มี UI ภาษาไทย, ครีเอเตอร์คุมหน้าร้านตัวเองไม่ได้มาก |
| [Artistree](https://artistree.io/) | ฟรีสำหรับศิลปิน + เก็บ platform fee ~6.5% จากลูกค้า | เมนู commission ที่มี scope/add-on/terms ชัด, จัดการ VAT/GST หลายประเทศ | fee ตกที่ลูกค้า ทำให้ราคาบวมในตลาดที่อ่อนไหวเรื่องราคา |
| [YCH.commishes](https://ych.commishes.com/) / YCH.art | ประมูล YCH & adopts | ระบบ auction สำหรับ YCH/adopt โดยเฉพาะ | UX เก่า, ไม่มีระบบจัดการคิว/ส่งมอบงานที่ดี |
| Ko-fi / Buy Me a Coffee | ทิป + shop | ฐานผู้ใช้ใหญ่ | commission เป็นฟีเจอร์รอง ไม่มี workflow จริง |
| Google Form + Twitter DM + PromptPay | ฟรี | ทุกคนใช้อยู่แล้ว | **นี่คือคู่แข่งตัวจริง** — งานหาย, ลืมคิว, ไม่มีหลักฐาน, TOS ไม่ผูกพัน |

**ข้อสรุปเชิงกลยุทธ์:** คู่แข่งที่ต้องเอาชนะไม่ใช่ VGen แต่คือ *"Google Form + DM"*
ดังนั้น free tier ต้องดีพอที่จะทำให้คนย้ายจาก Google Form ได้ทันที ถ้า free tier กั๊กเกินไป จะไม่มีใครย้ายมาตั้งแต่แรก

## 4. Personas

**A. ครีเอเตอร์ (ผู้ใช้หลัก / คนจ่ายเงิน)**
- นักวาด/นักตัดต่อ/คนทำ adopt อายุ 16–30 ส่วนใหญ่ทำเป็นงานเสริม
- เจ็บปวดกับ: คิวงานมั่ว, ลืมว่าใครจ่ายแล้ว, ลูกค้าขอแก้ไม่จบ, ไม่มี TOS ที่ลูกค้ายอมรับเป็นหลักฐาน
- **ต้องการ:** หน้าร้านที่ดูดี แปะลิงก์ใน bio ได้ + ที่เดียวที่เห็นว่างานไหนถึงไหน

**B. ลูกค้า (ผู้ใช้รอง / ไม่ต้องจ่ายให้แพลตฟอร์ม)**
- อยากจ้างวาด แต่ไม่รู้ว่าต้องบอกอะไรบ้าง / ต้องบรีฟยังไง
- **ต้องการ:** เห็นราคาชัด, รู้ว่าคิวยาวแค่ไหน, ติดตามความคืบหน้าได้โดยไม่ต้องทวงใน DM

**C. Admin แพลตฟอร์ม (เรา)**
- ดูแล abuse report, subscription, ระบบ

> **หลักการ:** ลูกค้าใช้ฟรีเสมอ เก็บเงินจากครีเอเตอร์เท่านั้น (ต่างจาก Artistree ที่เก็บจากลูกค้า)
> เหตุผล: ครีเอเตอร์คือคนที่ได้ ROI ชัด (ประหยัดเวลา ลดงานหลุด) และเป็นคนดึงลูกค้าเข้ามาเอง

## 5. Business model — ตัดสินใจแล้ว

### 5.1 โมเดลรายได้: **SaaS subscription** ไม่ใช่ marketplace fee

| ทางเลือก | ข้อดี | ข้อเสีย | ตัดสิน |
|---|---|---|---|
| หัก % จากทุกออเดอร์ (VGen model) | รายได้โตตามยอด GMV | ต้องถือเงินแทนคน → เข้าข่ายธุรกิจ e-payment ที่ต้องขอใบอนุญาตจาก ธปท., ต้องทำ KYC, dispute, refund, ภาษี | ❌ ไม่ทำใน Phase 1–3 |
| Subscription ปลดล็อกฟีเจอร์ | รายได้คาดเดาได้, ไม่แตะเงินคนอื่น, ความเสี่ยงทางกฎหมายต่ำมาก, ต้นทุนระบบต่ำ | ต้องมีฟีเจอร์ที่ "อยากจ่าย" จริง | ✅ **เลือกอันนี้** |

### 5.2 ผลที่ตามมา: **แพลตฟอร์มไม่ถือเงิน (no-escrow)**

นี่คือการตัดสินใจที่สำคัญที่สุดของโปรเจกต์ — เงินวิ่งจาก **ลูกค้า → ครีเอเตอร์โดยตรง**

การจ่ายเงินทำได้ 3 ทางในระบบ:
1. **PromptPay QR** — ระบบสร้าง QR (EMVCo payload) จาก PromptPay ID ของครีเอเตอร์ ฝั่ง client ทั้งหมด เงินโอนตรงธนาคารต่อธนาคาร เราไม่แตะเงินเลย ✨ *เหมาะกับตลาดไทยที่สุด และต้นทุน 0*
2. **ลิงก์จ่ายเงินของครีเอเตอร์เอง** — PayPal.me / Stripe Payment Link / Ko-fi ครีเอเตอร์แปะเอง
3. **บันทึกด้วยตนเอง** — โอนแล้วแนบสลิป ครีเอเตอร์กดยืนยัน → ระบบเก็บเป็น `payment_record`

ระบบทำหน้าที่ **บันทึกและ gate** เท่านั้น เช่น ไฟล์ final จะปลดล็อกให้ลูกค้าดาวน์โหลดก็ต่อเมื่อ `payment_record` ครบยอด

> Escrow จริง (Stripe Connect) ยกไปเป็น **Phase 4 (optional)** เมื่อมี traction พอที่จะคุ้มกับต้นทุน compliance
> schema ใน `02-data-model` ออกแบบให้รองรับทั้งสองแบบตั้งแต่แรก จึงไม่ต้อง migrate ใหญ่

### 5.3 ราคา (ตั้งต้น)

| Plan | ราคา | กลุ่มเป้าหมาย |
|---|---|---|
| **Free** | ฿0 | มือใหม่ / รับงานเป็นครั้งคราว |
| **Pro** | ฿159/เดือน หรือ ฿1,590/ปี (ฟรี 2 เดือน) | รับงานประจำ มีคิวตลอด |
| **Studio** | ฿499/เดือน | ทีม / สตูดิโอเล็ก (Phase 4) |

รับเงิน subscription ผ่าน **Stripe Billing** (เปิดให้ธุรกิจไทยแล้ว รองรับบัตร + PromptPay + subscription) → [Stripe launches in Thailand](https://stripe.com/newsroom/news/thailand)

## 6. Core loops (flow หลักที่ต้องทำให้ลื่นที่สุด)

### Loop 1 — ครีเอเตอร์เปิดร้าน (ครั้งเดียว, ต้องเสร็จใน < 10 นาที)
```
Login Google → เลือก handle (slug) → สร้าง service แรกจาก template
→ อัปโหลดผลงาน 3 ชิ้น → เลือก TOS template → กด Publish → ได้ลิงก์ theplatform.com/@handle
```
**Design goal:** onboarding แบบ wizard 4 ขั้น มี template ให้เลือก ไม่ต้องกรอกจากศูนย์

### Loop 2 — ลูกค้าสั่งงาน
```
เปิด /@handle → เห็นสถานะร้าน (เปิด/ปิด/waitlist) + คิวปัจจุบัน
→ เลือก service + add-on → เห็นราคารวมทันที (คำนวณสด)
→ กรอกฟอร์มบรีฟ (ฟอร์มที่ครีเอเตอร์ออกแบบเอง) → แนบ reference
→ Login Google → ติ๊กยอมรับ TOS → ส่งคำขอ
```
**Design goal:** ให้ลูกค้ากรอกฟอร์มได้ก่อน แล้วค่อยบังคับ login ตอนกดส่ง (ลด drop-off)

### Loop 3 — ครีเอเตอร์จัดการงาน (loop ที่ใช้บ่อยที่สุด)
```
แจ้งเตือน → เปิด Kanban board → ลากการ์ดข้าม column
requested → quoted → accepted → in_progress → review → delivered → completed
```
รองรับ 2 โหมดตาม VGen:
- **Instant order** — ราคาตายตัว ลูกค้าจ่ายแล้วเข้าคิวเลย ไม่ต้องเสนอราคา
- **Custom proposal** — ครีเอเตอร์ดูบรีฟก่อน แล้วส่งใบเสนอราคา (scope + timeline + milestone)

### Loop 4 — ส่งงาน
```
อัปโหลด WIP (ติดลายน้ำอัตโนมัติ) → ลูกค้า comment/ขอแก้ (นับโควตา revision)
→ อัปโหลด final (เก็บใน private blob) → ยืนยันการชำระเงินครบ → ปลดล็อกดาวน์โหลด
→ ลูกค้าให้ rating → ขึ้น public review บนหน้าร้าน
```

### Loop 5 — Adopts / YCH (ตัวสร้างความต่าง)
```
สร้าง listing (adopt / YCH / base) → ตั้งราคาตาย หรือ เปิดประมูล
→ ประมูล + anti-snipe (ต่อเวลาอัตโนมัติถ้ามีบิดช่วงท้าย)
→ ปิดประมูล → ผู้ชนะกลายเป็น order อัตโนมัติ → เข้า Loop 4
```

## 7. ขอบเขตที่ **ไม่ทำ** (Non-goals)

การเขียนสิ่งที่ไม่ทำสำคัญพอ ๆ กับสิ่งที่ทำ — ทั้งหมดนี้คือของที่ "ดูน่าทำ" แต่จะกินทรัพยากรจนโปรเจกต์ไม่จบ

- ❌ **แชทแบบ realtime ทั้งแพลตฟอร์ม** — ใช้ thread ผูกกับ order + polling เท่านั้น (เหตุผลเชิงต้นทุนอยู่ใน `01-architecture §6`)
- ❌ **Feed / social network / follow system** — เป็น commission tool ไม่ใช่ ArtStation
- ❌ **แอป iOS/Android native** — PWA + Web Push พอ (Web Push ทำงานบน iOS 16.4+ แล้ว)
- ❌ **AI generate art** — ขัดกับจุดยืนของชุมชนอาร์ตโดยตรง (VGen ถึงกับใช้ tagline "For the love of human creativity")
- ❌ **Escrow / ถือเงิน** ใน Phase 1–3
- ❌ **NFT / crypto**
- ❌ **Marketplace discovery ที่ซับซ้อน** ใน Phase 1 — `/explore` เริ่มจาก list เรียบ ๆ ก่อน ยังไม่ทำ ranking algorithm

## 8. Success metrics

| ระยะ | ตัวชี้วัด | เป้า |
|---|---|---|
| Activation | % ผู้สมัครที่ publish หน้าร้านสำเร็จ | > 40% |
| Core value | % ครีเอเตอร์ที่ได้รับ order แรกภายใน 14 วัน | > 25% |
| Retention | ครีเอเตอร์ที่ active (มี order ขยับ) ใน 30 วัน | > 30% |
| Conversion | Free → Pro | 3–6% |
| Cost | ค่าโครงสร้างพื้นฐานต่อครีเอเตอร์ active ต่อเดือน | < ฿3 |

> ตัวสุดท้ายคือเหตุผลที่ `01-architecture` ให้ความสำคัญกับ caching และ client-direct upload มาก

## 9. ความเสี่ยงหลัก

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| Cold start ไม่มีครีเอเตอร์ → ไม่มีลูกค้า | สูง | โฟกัสเป็น **tool ก่อน marketplace** — ครีเอเตอร์ได้ประโยชน์ตั้งแต่วันแรกแม้ยังไม่มีใครใช้ เพราะเอาลิงก์ไปแปะ bio Twitter/X ได้เลย |
| ผู้ใช้อัปโหลดไฟล์ใหญ่จน Blob บาน | ปานกลาง | บีบอัด/ย่อฝั่ง browser ก่อนอัปโหลด + quota ต่อ plan + GC ไฟล์กำพร้า |
| Neon compute hours หมดตั้งแต่ยังไม่มีรายได้ | ปานกลาง | cache หน้า public ด้วย `use cache` ให้ traffic ส่วนใหญ่ไม่แตะ DB |
| สแปมคำขอ commission | ปานกลาง | Vercel BotID + rate limit + ต้อง login ก่อนส่ง |
| ข้อพิพาทระหว่างครีเอเตอร์–ลูกค้า | ปานกลาง | ไม่ถือเงิน = ไม่ต้องตัดสิน แต่เก็บ audit log + thread ไว้เป็นหลักฐานให้ทั้งสองฝ่าย |
| ครีเอเตอร์ใช้ฟรีตลอดชาติ | ต่ำ–ปานกลาง | ฟีเจอร์ Pro ต้องผูกกับ "งานเยอะขึ้น" (คิวไม่จำกัด, แจ้งเตือนทันที, waitlist) → ยิ่งโตยิ่งอยากจ่าย |
| ปัญหาลิขสิทธิ์ / เนื้อหา NSFW | ปานกลาง | ธง `isMature` ต่อหน้าร้าน + ระบบ report + TOS ที่ครีเอเตอร์ต้องยอมรับ |
