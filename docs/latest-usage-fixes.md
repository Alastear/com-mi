# ผลแก้ไขจากการทดสอบใช้งาน

## สิ่งที่เพิ่มและแก้ไข

- ตอนเผยแพร่ร้าน นำเข้ารูป Google ไปเก็บในพื้นที่ของระบบ ถ้ายังไม่มีรูปที่อัปโหลดเอง
  และแจ้งเตือนหากนำเข้าไม่สำเร็จ แก้ fallback กรณี URL รูปเป็นข้อความว่าง
- เพิ่ม `/files` สำหรับค้นหา กรองประเภท ดูพื้นที่รวมไฟล์ที่กำลังอัปโหลด และเข้าไป
  จัดการจากร้านหรือออเดอร์ที่เกี่ยวข้อง แบ่งหน้าครั้งละ 50 ไฟล์
- เพิ่มพื้นที่ Free 5 GB, Pro 50 GB, Studio 200 GB เบต้าคงให้สิทธิ์ Pro
- เพิ่มการตั้งค่าบัญชีธนาคารและ TrueMoney Wallet พร้อมเลือกช่องทางแจ้งโอนในออเดอร์
  ข้อมูลรับเงินไม่ถูกส่งไปใน payload ของหน้าร้านสาธารณะ
- ปุ่มยกเลิกออเดอร์ถามทุกครั้ง รวมกรณีไม่มีรายการเงิน ปุ่มยกเลิกลิงก์เชิญมี dialog ด้วย
  ปรับปุ่มส่วนกลางให้เห็นเส้นขอบ พื้นหลัง และสถานะคลิกชัดขึ้น
- เพิ่มการส่งภาพตัวอย่าง PNG/JPEG/WebP โดยย่อและฝังลายน้ำในภาพก่อนอัปโหลด
  เก็บในถังส่วนตัวแยกจากไฟล์ต้นฉบับ พร้อมประวัติและแจ้งเตือน
- ลูกค้ากดยืนยันตัวอย่างล่าสุดก่อนการยืนยันรับเงินงวดสุดท้ายระหว่างทำงาน
  การส่งตัวอย่างใหม่หรือเปิดรอบแก้ล้างการยืนยันเดิม บังคับซ้ำใน SQL ใต้ order lock
  การจ่ายเต็มล่วงหน้าก่อนเริ่มงานยังรองรับ และผู้รับงานบันทึกเองได้เฉพาะมัดจำ
- เพิ่มการเปิดดูภาพหรือวิดีโอในไฟล์ส่งมอบ โดยใช้ด่านจ่ายครบและปลดล็อกเดียวกับดาวน์โหลด
  การดูตัวอย่างไม่ถูกนับเป็นการดาวน์โหลดครั้งแรกของลูกค้า
- กระดิ่งใช้ร่วมในหน้าแรกและหน้าจัดการ อ่านรายรายการ/อ่านทั้งหมดได้
  ลดตัวเลขหลังบันทึกสำเร็จ ปรับ ETag และส่งสัญญาณให้แท็บอื่นโหลดสถานะใหม่

## การรับเงินผ่านแพลตฟอร์มแบบซ่อนชื่อ

ยังไม่เปิดรับเงินจริง มีสูตรคำนวณและ tests ตามนโยบายหักค่าธรรมเนียมจากผู้รับงาน
รายละเอียดราคาและเงื่อนไขเปิดใช้งานอยู่ใน `payment-privacy-rollout.md`
ต้องยืนยันประเทศบัญชี Stripe และรูปแบบ Connect ที่รองรับการเก็บค่าธรรมเนียม
พร้อมตรวจชื่อที่ปรากฏใน Checkout ใบเสร็จ และรายการเดินบัญชี

## การติดตั้งและตรวจสอบ

รัน migrations `0026_absent_frightful_four` และ `0027_happy_gorilla_man`
กับฐานข้อมูลตาม env ที่ผู้ใช้เพิ่มให้แล้วเมื่อ 2026-10-05 ใน transaction เดียว
ตรวจประวัติเดิมทั้ง 26 รายการด้วย SHA-256 หลัง normalize CRLF เป็น LF แล้วตรงกัน
ตรวจยืนยันคอลัมน์ใหม่ทั้งหกเป็น nullable text ตาม schema ไม่แก้ข้อมูลผู้ใช้เดิม

Unit/regression tests ผ่าน 509 ข้อ และ production build ผ่าน รวมการตรวจ TypeScript
แก้การอ่านบรรทัด CRLF และ path ของ source tests เพื่อให้รันบน Windows ได้
ทดสอบนโยบายอนุมัติงานและค่าธรรมเนียมซ้ำหลัง migration ผ่าน 10 ข้อ
ยังไม่ได้ทดสอบออเดอร์ผ่านเบราว์เซอร์แบบสองบัญชี และยังไม่ได้สร้าง session ทดสอบ
สคริปต์ seed เดิมระบุว่าเคยใช้ฐานข้อมูลร่วมกับ production จึงต้องแยกข้อมูล QA อย่างชัดเจน

## รายการ QA ที่ยังต้องทำกับสภาพแวดล้อมทดสอบ

1. ใช้บัญชี Google ที่ไม่เปลี่ยนรูป เผยแพร่และเปิดหน้าร้านจากอีกเบราว์เซอร์
2. เพิ่ม/ล้างข้อมูลรับเงินทีละช่องทาง ตรวจว่าสาธารณะไม่เห็นเลขบัญชีหรือเบอร์ Wallet
3. ทดสอบมัดจำและจ่ายเต็มล่วงหน้า แล้วทดสอบงวดสุดท้ายหลังเริ่มงาน
4. ส่งภาพตัวอย่าง ตรวจว่าต้นฉบับไม่ถูกอัปในขั้นตอนนี้ ลูกค้ายืนยันแล้วส่งภาพใหม่
   ทดสอบว่าปุ่มรับเงินถูกบล็อกอีกครั้ง รวมการทำรายการพร้อมกันจากสองแท็บ
5. ตรวจภาพ/วิดีโอส่งมอบก่อนและหลังปลดล็อก งานที่ยังไม่จ่ายครบต้องเปิดไม่ได้
6. กดยกเลิกออเดอร์และลิงก์เชิญ เลือกกลับใน dialog ต้องไม่เปลี่ยนข้อมูล
7. เปิดกระดิ่งในหน้าแรก อ่านรายการและอ่านทั้งหมด ตรวจจำนวนหลัง refresh และอีกแท็บ
8. ตรวจปุ่มที่มือถือและทั้งสองธีม รวมโฟกัสด้วยคีย์บอร์ด
9. ตรวจหน้าจัดการไฟล์เมื่อไม่มีไฟล์ ค้นหาไม่พบ พื้นที่ใกล้เต็ม และมีหลายหน้า

ปรับ schema ของฐานข้อมูลที่กำหนดใน env แล้วตามรายการข้างต้น
การ deploy ใช้ Vercel ที่ผู้ใช้เชื่อมกับ GitHub โดย push เข้า main จะเริ่ม deploy อัตโนมัติ
ตรวจ production build ล่าสุดก่อนส่งขึ้น main ผ่านแล้ว
